# Техническое задание

## 1. Общие сведения

Наименование проекта:

«Налоговый навигатор» (чат-помощник для поиска материалов о налоговых изменениях).

Заказчик:

Учебный проект.

Тип проекта:

Веб-приложение с чат-помощником для поиска и показа выдержек из загруженных налоговых материалов. При подключении большой языковой модели (LLM) доступен автоматический пересказ.

Команда разработки:

- Мухамедзянов Матвей;
- Данила Марченков.
## 2. Цель разработки

Целью проекта является разработка веб-приложения с чат-помощником, позволяющим пользователю находить сведения о налоговых изменениях на выбранную дату и проверять их по источникам.

Приложение должно предоставлять возможность задавать вопросы в формате диалога, искать релевантные фрагменты в загруженных документах и показывать их с указанием источников.

## 3. Задачи проекта

В рамках разработки необходимо:

1. Проанализировать предметную область и определить основные сценарии использования ИИ-помощника.

2. Спроектировать архитектуру веб-приложения.

3. Разработать клиентскую часть приложения.

4. Разработать серверную часть и REST API.

5. Предусмотреть подключение LLM для формирования пересказа по найденным фрагментам.

6. Реализовать поиск информации по налоговому законодательству и связанным материалам.

7. Реализовать механизм извлечения релевантных фрагментов документов для показа пользователю и передачи в LLM при её подключении.

8. Реализовать чат-интерфейс для взаимодействия пользователя с ИИ-помощником.

9. Реализовать отображение источников, использованных при подготовке ответа.

10. Реализовать хранение истории диалогов и пользовательских запросов.

11. Реализовать регистрацию и авторизацию пользователей.

12. Провести тестирование и исправление выявленных ошибок.

## 4. Функциональные требования

### 4.1. Регистрация и авторизация

Пользователь должен иметь возможность:

- зарегистрироваться в системе;
- выполнить вход в аккаунт;
- выйти из аккаунта;
- просматривать данные профиля и изменять имя.
Для защиты пользовательских данных должна использоваться JWT-аутентификация. Пароли пользователей должны храниться в базе данных в хешированном виде.

### 4.2. Чат с ИИ-помощником

Пользователь должен иметь возможность:

- задавать вопросы о налоговых изменениях;
- получать краткую или подробную подборку выдержек из документов;
- задавать уточнения в рамках одного диалога. Для поддерживаемых коротких уточнений поиск может учитывать предыдущий вопрос;
- просматривать историю сообщений;
- начинать новый диалог.
Ответ должен показывать найденные выдержки со ссылками или сведениями об источниках. При подключённой LLM доступен пересказ по найденным фрагментам.

### 4.3. Поиск и обработка налоговых изменений

Система должна обеспечивать полнотекстовый поиск по загруженным материалам налогового законодательства и связанным документам.

Поисковый модуль должен:

- принимать естественно-языковой запрос пользователя;
- находить релевантные документы и фрагменты;
- учитывать дату публикации и период действия материала на выбранную пользователем дату;
- показывать найденные фрагменты и при подключённой LLM передавать их модели для формирования ответа.
При отсутствии достаточной информации система должна сообщать пользователю об ограниченности найденных данных и не формировать ответ как достоверный факт без подтверждающего источника.

### 4.4. Представление найденных изменений

В основном режиме помощник показывает выдержки из документов. При подключённой LLM возможен пересказ. Если модель недоступна или возвращает некорректные ссылки, система показывает выдержки.

Ответ может включать:

- что изменилось;
- с какой даты действует изменение;
- кого касается изменение;
- основные условия и ограничения;
- ссылку или название источника.
### 4.5. История диалогов

Система должна сохранять:

- вопросы пользователя;
- ответы ИИ-помощника;
- дату и время сообщений;
- идентификатор диалога.
Пользователь должен иметь возможность просматривать ранее созданные диалоги.

### 4.6. Административная часть

Администратор должен иметь возможность:

- просматривать пользователей;
- управлять доступом пользователей;
- просматривать историю запросов и техническую статистику;
- добавлять и отключать источники, загружать документы в формате JSON и удалять их. При загрузке документы индексируются.
## 5. Нефункциональные требования

Приложение должно:

- иметь понятный и адаптивный пользовательский интерфейс;
- корректно работать в современных браузерах;
- обеспечивать безопасную обработку пользовательских данных;
- использовать клиент-серверную архитектуру;
- обеспечивать разграничение доступа к защищённым ресурсам;
- сохранять историю диалогов;
- иметь модульную структуру, позволяющую заменять LLM и добавлять новые источники данных;
- учитывать актуальность и дату налоговой информации;
- минимизировать риск выдачи неподтверждённой информации.
## 6. Используемые технологии

Frontend

- React;
- TypeScript;
- React Router;
- CSS.
Backend

- Node.js;
- Express;
- TypeScript;
- REST API;
- JWT;
- bcrypt.
Database

- PostgreSQL;
- библиотека pg.
ИИ и поиск

- совместимый LLM API для дополнительного режима пересказа;
- полнотекстовый поиск PostgreSQL по фрагментам загруженных документов;
- фильтрация по дате публикации, периоду действия и статусу источника.
Архитектура

Серверная часть должна разрабатываться с использованием модульного архитектурного подхода с разделением контроллеров, сервисов и моделей.

Общая схема взаимодействия компонентов:

React → REST API → Express → сервис поиска → PostgreSQL → выдержки и ссылки пользователю. При подключённой LLM найденные фрагменты передаются модели для пересказа.

## 7. Основные сущности базы данных

В базе данных предусматривается создание следующих основных таблиц:

- users — пользователи системы;
- chats — диалоги пользователей;
- messages — сообщения пользователей и ответы ИИ;
- sources — источники налоговой информации;
- documents — документы и материалы законодательства;
- document_chunks — фрагменты документов для поиска;
- search_history — история поисковых запросов.
Для хранения дополнительных метаданных документов и результатов поиска допускается использование типа JSONB PostgreSQL.

## 9. Ожидаемый результат

В результате разработки должно быть создано веб-приложение «Налоговый навигатор» с чат-помощником по налоговым изменениям.

Приложение должно включать:

- регистрацию и авторизацию;
- чат-интерфейс с кратким и подробным режимами;
- поиск по загруженным налоговым материалам с учётом выбранной даты;
- показ найденных выдержек и возможность подключить LLM для автоматического пересказа;
- отображение источников информации;
- сохранение истории диалогов;
- личный кабинет пользователя;
- административную часть;
- базу данных PostgreSQL;
- REST API для взаимодействия клиентской и серверной частей.
Разработанное приложение должно иметь модульную архитектуру, позволяющую в дальнейшем добавлять новые источники налоговой информации, улучшать алгоритмы поиска, подключать другие LLM и расширять возможности ИИ-помощника.

# Формат импорта документа

В «Управление» выберите источник, затем JSON-файл в UTF-8. `source_id` подставляется интерфейсом. Для API его нужно передать явно.

```json
{
  "title": "Полное название проверенного документа",
  "url": "https://official.example/document",
  "published_on": "2026-01-01",
  "effective_from": "2026-02-01",
  "effective_to": null,
  "demo": false,
  "content": "Полный проверенный текст или законченный фрагмент документа..."
}
```

Адрес выше — образец структуры, его нельзя использовать как источник. Замените его точной ссылкой. В отличие от этого шаблона, `data/demo-document.json` готов к импорту как вымышленный пример.

| Поле | Правило |
|---|---|
| title | 3–300 символов |
| url | HTTPS-ссылка обязательна для реального документа, для учебного может быть null |
| published_on | Реальная календарная дата YYYY-MM-DD |
| effective_from | Первый день применимости |
| effective_to | Последний день применимости включительно, либо null |
| demo | true для вымышленных учебных данных; по умолчанию false |
| content | От 30 до 200 000 символов |

HTTP-тело ограничено 1 МБ; интерфейс принимает файл до 900 000 байт. Импорт одного документа и его фрагментов выполняется в общей транзакции. При ошибке документа его фрагменты не сохраняются.

Индексируется название и текст. Размер фрагмента — 1200 символов, перекрытие — 160. Для качественного ответа загружайте контекст, включающий условия, категории налогоплательщиков и даты, а не отдельные числа. Не смешивайте разные редакции нормы в одном документе. При изменении нормы заполните период старой редакции и загрузите новую. Текущая версия не извлекает даты и реквизиты автоматически.

Наличие HTTPS-ссылки — проверка формата, не проверка юридической достоверности. Откройте первоисточник и проверьте содержание вручную. Загруженный текст не считается инструкцией для LLM; он передаётся как недоверенные данные.
